# Извлечение именованных сущностей (NER)

## Описание проекта
Проект посвящён распознаванию именованных сущностей — персон (`PER`), организаций (`ORG`) и локаций (`LOC`) — в русскоязычных текстах для сервиса медиамониторинга «Эхолот». Модель `bert-base-multilingual-cased` дообучается для задачи token classification, а главный исследовательский вопрос — как качество зависит от объёма размеченных данных.

Проект разделён на две тетрадки:
1. **Анализ и подготовка данных:** разбор разметки IOB2 датасета WikiANN, распределение типов сущностей и длин предложений, токенизация и выравнивание NER-меток с подтокенами BERT (`word_ids()`, метка `-100`), проверка динамического паддинга.
2. **Обучение и эксперименты:**
   - метрики на уровне целых сущностей через `seqeval` (общие и по каждому типу);
   - baseline — BERT с необученной NER-головой;
   - дообучение на 100 примерах с подбором `learning_rate` по валидационному F1;
   - дообучение на 1000 примерах с выбранными настройками;
   - сравнение моделей, классификация ошибок (пропуск, неверный тип, неправильные границы, лишняя сущность) и поиск расхождений между моделями;
   - сохранение и повторная загрузка модели, инференс через `pipeline` на собственных предложениях.

## Структура проекта
- `Извлечение именованных сущностей. Часть 1 — анализ данных.ipynb` — исследование данных, токенизация и выравнивание меток.
- `Извлечение именованных сущностей. Часть 2 — эксперименты.ipynb` — обучение моделей, сравнение, анализ ошибок и рекомендации.
- `requirements.txt` — список необходимых Python-библиотек для запуска.

## Данные
Используется русскоязычная конфигурация открытого датасета [WikiANN](https://huggingface.co/datasets/unimelb-nlp/wikiann) (20 000 / 10 000 / 10 000 предложений в train / validation / test). Датасет и токенизатор загружаются с Hugging Face автоматически, дополнительная настройка не требуется.

> Чекпоинты и сохранённая модель (`bert-ner-*`, `saved_ner_model/`) создаются при запуске второй тетрадки и не хранятся в репозитории.

## Установка и запуск

1. Перейдите в папку с проектом.
2. Рекомендуется создать виртуальное окружение:
   ```bash
   python -m venv venv
   source venv/bin/activate  # Для Windows используйте: venv\Scripts\activate
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Запустите тетрадки по порядку (для второй части желательно наличие GPU):
   ```bash
   jupyter notebook "Извлечение именованных сущностей. Часть 1 — анализ данных.ipynb"
   ```

## Краткие выводы
- Baseline без дообучения практически не распознаёт сущности (F1 = **0.0341**), что подтверждает необходимость fine-tuning.
- Дообучение всего на **100** примерах (`learning_rate = 5e-5`, выбран по валидации) даёт F1 = **0.4691**; увеличение выборки до **1000** примеров поднимает F1 до **0.8075** (+72%): `PER` — 0.9133, `LOC` — 0.8248, `ORG` — 0.7019.
- Сильнее всего от объёма данных выигрывают организации (`ORG`, F1 вырос более чем вдвое) — самый вариативный класс.
- Самый частый тип ошибок итоговой модели — «лишняя сущность» (37.4%); часть таких ошибок объясняется неполнотой автоматической разметки WikiANN.
- Для внедрения в «Эхолот» рекомендуется разметить 1–2 тыс. текстов из собственного медиапотока (доменный сдвиг относительно Википедии) с акцентом на организации, а для F1 > 0.9 — 5–10 тыс. текстов.
