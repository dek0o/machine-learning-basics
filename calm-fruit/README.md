# Семантический поиск товаров

## Описание проекта
Маркетплейс CalmFruits проверяет, улучшает ли векторный поиск товаров по текстовому запросу существующий поиск по ключевым словам. MVP решает задачу query-to-item: по короткому запросу пользователя система возвращает top-K карточек товара (`imt_id`) из каталога одежды и обуви.

Сравниваются лексический поиск (TF-IDF) и семантический поиск на эмбеддингах `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` с одинаковым интерфейсом `search_xxx(query, top_k)`, а также три эксперимента по улучшению:
1. **Этап 1 — EDA:** выбор категорий MVP, правил очистки описаний и полей текста товара.
2. **Этап 2 — базовый пайплайн:** подготовка каталога, индексы TF-IDF и MiniLM, протокол оценки на golden-сете (Precision@K, Recall@K, MRR, NDCG@K, HitRate@K), разбор ошибок.
3. **Этап 3 — эксперименты:** короткий текст товара для эмбеддингов, гибрид TF-IDF и MiniLM через Reciprocal Rank Fusion, обучаемая проекция поверх замороженного энкодера; трекинг всех конфигураций в MLflow и единственный финальный прогон на test.

## Структура проекта
- `Семантический поиск товаров.ipynb` — основной Jupyter Notebook: EDA, пайплайн, оценка, эксперименты, MLflow и выводы.
- `check_mlflow.py` — проверка эксперимента MLflow (наличие прогонов, метрик и параметров).
- `requirements.txt` — зафиксированные зависимости (Python 3.12, вычисления на CPU).
- `.env.example` — шаблон файла переменных окружения для доступа к S3 и MLflow.

При выполнении ноутбук создаёт папки `data/` (скачанные исходные файлы) и `artifacts/` (эмбеддинги, метрики по запросам, графики, результат финального теста). Обе папки не хранятся в репозитории и полностью воспроизводятся ноутбуком.

## Данные
Исходные файлы читаются из S3-хранилища и сохраняются в `data/`:

| Файл | Назначение |
| --- | --- |
| `wb_products_raw_sample.parquet` | сырой каталог (~200 тыс. строк), из него готовятся тексты товаров |
| `wb_products_dedup.parquet` | список `imt_id` пула асессоров для каталога оценки |
| `queries_synthetic_train.parquet` | разметка для baseline, подбора параметров и валидации |
| `queries_synthetic_test.parquet` | один финальный прогон выбранной конфигурации |

Разметка содержит `query_id`, `query_text`, `item_id` и `relevance` по шкале 0–3. Тестовая разметка используется один раз — после выбора конфигурации по validation.

> Параметры доступа к хранилищу (`S3_ENDPOINT_URL`, `S3_BUCKET`, ключи) и к MLflow (`MLFLOW_TRACKING_URI`, логин, пароль) задаются в файле `.env`.

## Установка и запуск

1. Перейдите в папку с проектом.
2. Рекомендуется создать виртуальное окружение:
   ```bash
   python3.12 -m venv venv
   source venv/bin/activate  # Для Windows используйте: venv\Scripts\activate
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Создайте конфигурационный файл `.env` на основе шаблона и заполните параметры доступа:
   ```bash
   cp .env.example .env
   ```
5. Запустите Jupyter Notebook (полный прогон на CPU занимает около 6 минут):
   ```bash
   jupyter notebook "Семантический поиск товаров.ipynb"
   ```
6. При необходимости проверьте эксперимент MLflow отдельно:
   ```bash
   python check_mlflow.py calmfruits_semantic_search --env-file .env
   ```

## Краткие выводы
Каталог оценки — 4 256 карточек категорий «Одежда» и «Обувь»; golden-сет — 140 validation-запросов; порог релевантности `relevance >= 2`, NDCG по шкале 0–3.

| Конфигурация | Выборка | NDCG@10 | MRR | Recall@10 | HitRate@10 |
| --- | --- | ---: | ---: | ---: | ---: |
| RRF-гибрид TF-IDF + MiniLM (выбран) | validation | 0,460 | 0,157 | 0,339 | 0,450 |
| TF-IDF (baseline) | validation | 0,459 | 0,169 | 0,320 | 0,450 |
| MiniLM, полный текст | validation | 0,231 | 0,117 | 0,171 | 0,257 |
| MiniLM, короткий текст | validation | 0,188 | 0,144 | 0,214 | 0,286 |
| MiniLM + обучаемая проекция | validation | 0,096 | 0,136 | 0,146 | 0,229 |
| RRF-гибрид TF-IDF + MiniLM | test (300 запросов) | 0,424 | 0,152 | 0,296 | 0,407 |

- Чистый семантический поиск вдвое уступает лексическому: MiniLM путает смежные типы одежды и обуви и не удерживает тип товара, названный в запросе явно.
- Гибрид с малым весом семантики равен TF-IDF по NDCG@10 и немного полнее по Recall@10 — он выбран как итоговая конфигурация.
- Ограничения: синтетическая пулированная разметка, небольшие выборки и большая доля карточек без описания. Рекомендация бизнесу, разбор ошибок и дальнейшие шаги — в конце ноутбука.
